## Algorithm overview

**RadiusNeighborsRegressor** predicts a query sample's continuous target by averaging (uniformly or by inverse distance) all training observations within a fixed `radius` of the query. Unlike [`KNeighborsRegressor`](/docs/apis/neighbors/kneighborsRegressor), which always averages `k` points no matter how far away they sit, radius regression refuses to average over distant unrelated observations—returning `Number.NaN` wherever a query falls in an empty gap of the feature space.

This makes `RadiusNeighborsRegressor` ideal for spatial interpolation, physical sensor lookup tables, and uneven tabular regions where you want local smoothing inside dense clusters and explicit `NaN` uncertainty markers outside known coverage.

## JavaScript implementation

`@kanaries/ml` provides `Neighbors.RadiusNeighborsRegressor` in pure TypeScript for browser and Node.js applications, supporting `'uniform'` and `'distance'` weighting, all `Metrics.Distance` metrics, [`Pipeline`](/docs/apis/pipeline) composition, and JSON serialization via `toJSON()` / [`loadModel()`](/docs/apis/serialization).

## Quick start example

```ts
import { Neighbors } from '@kanaries/ml';

const reg = new Neighbors.RadiusNeighborsRegressor({ radius: 1.25, weights: 'distance' });
reg.fit([[0], [1], [4]], [0, 1, 4]);
const pred = reg.predict([[0.5], [10]]);
console.log(pred); // [0.5, NaN]
```

## Detailed API reference

### `new Neighbors.RadiusNeighborsRegressor(props?)`

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `radius` | `number` | `1.0` | Neighborhood radius for selecting contributing training points. |
| `weights` | `'uniform' \| 'distance'` | `'uniform'` | Equal average (`'uniform'`) or inverse-distance weighted average (`'distance'`). |
| `metric` / `p` | `Distance.IDistanceType` / `number` | `'euclidean'` / `2` | Distance metric and Minkowski exponent. |

### Methods & practical tips

- `fit(trainX, trainY)` / `predict(testX)` — check `Number.isNaN(pred)` when handling out-of-coverage queries in production UIs.
- Always scale features with [`StandardScaler`](/docs/apis/utils/preprocessing) so a single scalar `radius` treats every dimension evenly.
