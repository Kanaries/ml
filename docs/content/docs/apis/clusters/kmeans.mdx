## Algorithm overview

**K-Means** is an unsupervised partitioning algorithm that groups numeric observations into `n_clusters` compact clusters by minimizing within-cluster squared Euclidean distance (**inertia**). Each iteration alternates between assigning every sample to its nearest centroid and recomputing each centroid as the (optionally weighted) mean of its assigned points until the relative inertia improvement drops below `tol` or `max_iter` iterations complete.

K-Means is a strong first choice when:

- You can estimate or sweep a small range of cluster counts (`k = 2..10`) using elbow curves or [silhouette scores](/docs/apis/metrics).
- Clusters are roughly convex, spherical, and comparable in scale.
- You need fast, interpretable customer segmentation, product grouping, or vector quantization in production.

## JavaScript implementation

`@kanaries/ml` provides `Clusters.KMeans` in pure TypeScript for browsers and Node.js. It supports the canonical options-object constructor (`KMeansProps`) with k-means++ initialization, `n_init` restarts (keeping the lowest-inertia run), deterministic `random_state` seeding, optional per-sample weights, and full JSON persistence via `toJSON()` / [`loadModel()`](/docs/apis/serialization).

Unlike server-only Python pipelines, running `Clusters.KMeans` directly in the browser lets users adjust `k`, inspect centroids, and segment CSV uploads instantaneously without uploading private data. For very large embedding tables (10,000+ vectors), see [`Clusters.EMeans`](/docs/apis/clusters/eMeans) or run fitting inside a Web Worker.

## Quick start

```ts
import { Clusters } from '@kanaries/ml';

const X = [
  [0, 0],
  [0.5, 0],
  [0.5, 1],
  [1, 1],
  [8, 8],
  [8.5, 8.2],
];

const kmeans = new Clusters.KMeans({
  n_clusters: 2,
  tol: 1e-4,
  n_init: 10,
  random_state: 42,
});

const labels = kmeans.fitPredict(X);
console.log({ labels, centroids: kmeans.getCentroids(), inertia: kmeans.getInertia() });
```

## Detailed API reference

### `new Clusters.KMeans(props?)`

*(Legacy positional calls `new Clusters.KMeans(n_clusters, tol, initCenters, max_iter, random_state, n_init)` remain supported for backward compatibility, but prefer the options object.)*

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `n_clusters` | `number` | `2` | Number of clusters (`k`) to form. |
| `tol` | `number` | `1e-4` | Relative tolerance on weighted inertia change to declare convergence. |
| `initCenters` | `number[][]` | `undefined` | Optional explicit starting centroids (`[n_clusters][nFeatures]`). When supplied, `n_init` is forced to `1`. |
| `max_iter` | `number` | `30` | Maximum Lloyd iterations per restart. |
| `random_state` | `number` | `undefined` | Seed for reproducible k-means++ centroid initialization. |
| `n_init` | `number` | `10` | Number of independent k-means++ restarts; the run with the lowest weighted inertia is kept. |

### Methods

| Method | Signature | Description |
| --- | --- | --- |
| `fitPredict` | `(sampleX: number[][], sampleWeights?: number[]) => number[]` | Fits centroids on `sampleX` (optionally weighted) and returns integer cluster labels `0..n_clusters-1`. |
| `getCentroids` | `() => number[][] \| null` | Returns the fitted centroid coordinates (or `null` before fitting). |
| `getInertia` | `() => number` | Returns the sum of squared weighted distances of samples to their closest centroid. |
| `getParams` / `setParams` / `toJSON` | Inherited from `ClusterBase` | Full estimator contract & JSON serialization via [`loadModel()`](/docs/apis/serialization). |

### Practical guidance & pitfalls

- **Always standardize feature scales**: Because K-Means relies on squared Euclidean distance, a feature measured in thousands (`revenue`) will drown out a feature in `[0, 1]` (`churn_rate`). Scale columns first with [`StandardScaler`](/docs/apis/utils/preprocessing).
- **Choosing `k`**: Sweep `k` across candidate values and inspect both `getInertia()` (elbow curve) and [`Metrics.silhouetteScore`](/docs/apis/metrics).
- **Non-spherical or noisy clusters**: If clusters have arbitrary shapes or outliers, try [`Clusters.DBSCAN`](/docs/apis/clusters/dbscan), [`Clusters.HDBSCAN`](/docs/apis/clusters/hdbscan), or [`Mixture.GaussianMixture`](/docs/apis/mixture/gaussian-mixture).
- **Related pages**: [E-Means](/docs/apis/clusters/eMeans), [Customer Segmentation CSV Guide](/docs/guides/customer-segmentation-csv), [K-Means Playground](/playground/kmeans), [Clustering Overview](/docs/apis/clusters).
