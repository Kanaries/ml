## Algorithm overview

Standard random K-Fold and train/test splits silently leak information whenever multiple observations belong to the same underlying **group**—such as repeated medical measurements from the same patient, multiple clicks from the same user session, or telemetry rows from the same IoT device. When rows from the same entity appear in both train and validation folds, a model can memorize entity idiosyncrasies and report artificially inflated accuracy that collapses on unseen users in production.

**Group-aware cross-validation splitters** enforce a strict invariant: every row sharing a `group` identifier is placed together on only one side of each train/test split:

- **`GroupShuffleSplit`**: generates `nSplits` random group-level train/test partitions where fractional `testSize`/`trainSize` refers to the fraction of **unique groups**, not rows.
- **`StratifiedGroupKFold`**: partitions groups into `nSplits` non-overlapping folds while greedily balancing **class label proportions** across folds—essential for imbalanced classification with grouped entities.

## JavaScript implementation

`@kanaries/ml` provides both splitters under `utils.ModelSelection` in pure TypeScript for browser and Node.js evaluation pipelines, supporting string or numeric group identifiers and deterministic `randomState` seeds.

## Quick start example

```ts
import { utils } from '@kanaries/ml';

const X = [[0], [1], [2], [3], [4], [5]];
const y = [0, 0, 1, 1, 0, 1];
const patientIds = ['a', 'a', 'b', 'b', 'c', 'c'];

const folds = new utils.ModelSelection.StratifiedGroupKFold({
  nSplits: 3,
  shuffle: true,
  randomState: 42,
}).split(X, y, patientIds);
console.log(folds);
```

## Detailed API reference

| Class | Options | `split()` return value |
| --- | --- | --- |
| `GroupShuffleSplit` | `{ nSplits = 5, testSize?, trainSize?, randomState? }` | `FoldIndices[]` (`{ trainIndices, testIndices }`) |
| `StratifiedGroupKFold` | `{ nSplits = 5, shuffle = false, randomState? }` | `FoldIndices[]` (`y` and `groups` required) |
